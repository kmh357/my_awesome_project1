# Project Requirements Document

## Project Overview
**Project Name:** 찍찍이 (Tick-Tick-E)
**Version:** 1.0.0
**Last Updated:** 2025-11-19
**Project Type:** 모바일/웹 애플리케이션

## Executive Summary
찍찍이(Tick-Tick-E)는 초등학생이 스스로 오늘의 할 일을 관리하고, 완료하면 칭찬 스티커를 받는 재미있는 할 일 관리 앱입니다. 이 앱은 아이들이 책임감과 성취감을 느끼며 자기 관리 습관을 기를 수 있도록 게임화(gamification) 요소를 접목하여, 지루한 할 일 관리를 즐거운 경험으로 전환합니다.

## 프로젝트 목적
초등학생들에게 할 일 관리는 어렵고 지루한 일로 느껴질 수 있습니다. 찍찍이는 긍정적 강화(칭찬, 스티커)를 통해 아이들이 자발적으로 할 일을 완수하고, 이를 통해 책임감과 성취감을 배울 수 있도록 돕습니다. 부모나 교사의 강요가 아닌, 스스로 동기부여를 받아 할 일을 관리하는 습관을 기르는 것이 핵심 목적입니다.

## Goals and Objectives
- **주요 목표**: 아이들이 즐겁게 책임감을 배우고 자기 관리 습관을 형성하도록 돕는다
- **구체적 목표**:
  - 할 일 관리를 재미있는 활동으로 만들어 아이들의 자발적 참여 유도
  - 긍정적 피드백(스티커, 칭찬)을 통한 성취감 제공
  - 단순하고 직관적인 UI로 초등학생도 쉽게 사용할 수 있는 앱 구현
  - 매일 사용하고 싶은 습관 형성 지원
- **측정 가능한 목표**:
  - 출시 후 3개월 내 일일 활성 사용자(DAU) 100명 달성
  - 사용자의 평균 주간 할 일 완료율 70% 이상 유지
  - 앱 재방문율 60% 이상 (주 3회 이상 사용)

## Target Audience
### 주 사용자
- **연령**: 초등학생 (7-13세)
- **특징**:
  - 글을 읽고 쓸 수 있는 수준
  - 스마트폰이나 태블릿 기본 조작 가능
  - 스티커, 칭찬 등 보상에 긍정적으로 반응
  - 게임적 요소에 흥미를 느낌

### 부차적 사용자
- **학부모**: 자녀의 자기 관리 습관 형성을 원하는 부모
- **교사**: 학생들의 숙제 및 과제 관리를 돕고자 하는 교육자

## Features and Requirements

### Core Features

#### 1. 할 일 추가 기능
- **Description**: 사용자가 오늘 또는 특정 날짜의 할 일을 직접 입력하고 추가할 수 있는 기능
- **Priority**: High (필수 기능)
- **상세 요구사항**:
  - 할 일 입력 필드: 최대 50자까지 입력 가능
  - 입력 예시 텍스트 표시 (placeholder): "예: 수학 숙제하기, 강아지 밥 주기"
  - "추가" 버튼 클릭 시 할 일이 목록에 즉시 추가됨
  - 빈 내용으로는 추가 불가 (유효성 검증)
  - 추가된 할 일은 리스트 맨 위 또는 맨 아래에 표시 (사용자 설정 가능)
  - 키보드의 Enter 키를 누르면 자동으로 추가되도록 구현
- **UI/UX 요구사항**:
  - 큰 글씨와 아이콘으로 직관적인 인터페이스
  - 밝고 친근한 색상 사용 (파스텔톤 추천)
  - "+" 버튼은 눈에 띄고 누르기 쉬운 크기 (최소 44x44px)
- **기술 요구사항**:
  - 입력된 데이터는 로컬 스토리지 또는 데이터베이스에 저장
  - 날짜별로 할 일을 구분하여 저장

#### 2. 할 일 완료 체크 기능
- **Description**: 사용자가 할 일을 완료했을 때 체크 표시를 할 수 있는 기능
- **Priority**: High (필수 기능)
- **상세 요구사항**:
  - 각 할 일 항목 옆에 체크박스 또는 원형 버튼 표시
  - 체크 시 할 일 항목에 취소선이 그어지거나 색상이 변경됨
  - 체크 해제 가능 (실수로 체크한 경우)
  - 체크/해제 시 부드러운 애니메이션 효과 (0.3초 정도)
  - 완료된 항목 수 / 전체 항목 수를 상단에 표시 (예: "3개 중 1개 완료!")
- **UI/UX 요구사항**:
  - 체크박스는 충분히 큰 크기로 제공 (터치하기 쉽게)
  - 체크 시 시각적 피드백 명확하게 제공 (색상 변화, 애니메이션)
  - 완료된 항목은 시각적으로 구분 (회색 처리, 취소선 등)
- **기술 요구사항**:
  - 체크 상태는 실시간으로 저장
  - 날짜별 완료율 통계 수집

#### 3. 스티커 받기 (보상 시스템)
- **Description**: 할 일을 완료하면 칭찬 메시지와 함께 예쁜 스티커를 받는 보상 기능
- **Priority**: High (핵심 차별화 기능)
- **상세 요구사항**:
  - 할 일 1개 완료 시 즉시 팝업 또는 모달 창 표시
  - 칭찬 메시지 랜덤 표시:
    - "참 잘했어요!"
    - "대단해요!"
    - "훌륭해요!"
    - "최고예요!"
    - "멋져요!"
  - 스티커 이미지를 화면 중앙에 크게 표시 (짠! 효과)
  - 스티커는 다양한 디자인 (별, 하트, 트로피, 동물, 이모지 등)
  - 스티커는 랜덤으로 지급 (수집의 재미)
  - 희귀 스티커 개념 도입 가능 (금색, 레인보우 등)
  - "확인" 버튼 클릭 시 스티커 모음판에 자동 저장
  - 애니메이션 효과: 스티커가 반짝이거나 회전하는 효과
  - 사운드 효과: 스티커 획득 시 짧고 경쾌한 소리 (선택적, 끄기 가능)
- **UI/UX 요구사항**:
  - 밝고 즐거운 분위기의 팝업 디자인
  - 아이들이 기쁨을 느낄 수 있는 비주얼 효과
  - 너무 오래 머물지 않도록 3-5초 후 자동 닫기 옵션
- **기술 요구사항**:
  - 스티커 이미지 리소스 관리
  - 스티커 획득 이력 데이터베이스 저장
  - 희귀도별 확률 로직 구현

#### 4. 스티커 모음판
- **Description**: 지금까지 받은 모든 스티커를 한눈에 볼 수 있는 컬렉션 페이지
- **Priority**: Medium (중요 기능)
- **상세 요구사항**:
  - 별도의 페이지 또는 탭으로 구성
  - 그리드 형태로 스티커 나열 (3x3, 4x4 등)
  - 획득한 스티커는 컬러로, 미획득 스티커는 실루엣 또는 잠금 아이콘으로 표시
  - 각 스티커 클릭 시 크게 보기 및 획득 날짜 표시
  - 전체 스티커 수 / 획득한 스티커 수 표시 (예: "35개 중 12개 수집!")
  - 스티커 종류별 카테고리 구분 (동물, 음식, 자연, 트로피 등)
  - 완성된 카테고리에 특별 배지 부여
- **UI/UX 요구사항**:
  - 보기 좋은 카드 형태로 스티커 배치
  - 스크롤 가능한 레이아웃
  - 수집 진행도 바(progress bar) 표시
- **기술 요구사항**:
  - 스티커 데이터 조회 및 필터링
  - 이미지 최적화 (빠른 로딩)

### Additional Features (향후 확장 가능)

#### 5. 할 일 삭제 및 수정
- **Description**: 잘못 입력한 할 일을 삭제하거나 내용을 수정할 수 있는 기능
- **Priority**: Medium
- **요구사항**:
  - 할 일 항목을 왼쪽이나 오른쪽으로 스와이프하여 삭제
  - 항목 클릭 시 수정 모드로 전환
  - 삭제 시 확인 메시지 표시 (실수 방지)

#### 6. 할 일 우선순위 설정
- **Description**: 중요한 할 일에 별표나 색상 표시
- **Priority**: Low
- **요구사항**:
  - 별 아이콘 클릭으로 중요 표시
  - 중요한 할 일은 목록 상단에 자동 정렬

#### 7. 부모 모드 (통계 보기)
- **Description**: 부모가 자녀의 할 일 완료 현황을 확인할 수 있는 기능
- **Priority**: Low (v2.0 고려)
- **요구사항**:
  - 주간/월간 완료율 그래프
  - 가장 많이 한 할 일 통계
  - 획득 스티커 현황

## User Stories

### 스토리 1: 학교 숙제 관리
> "초등학교 3학년 민지는 오늘 수학 숙제, 국어 일기 쓰기, 과학 관찰 일지 작성이라는 3가지 숙제가 있다. 학교에서 돌아오자마자 찍찍이 앱을 열어 세 가지 할 일을 모두 입력한다. 수학 숙제를 먼저 끝내고 체크 표시를 하자, '참 잘했어요!' 메시지와 함께 예쁜 강아지 스티커를 받았다. 민지는 기뻐하며 나머지 숙제도 빨리 끝내고 스티커를 더 모으고 싶다는 생각이 든다."

### 스토리 2: 하루 일과 계획하기
> "초등학교 5학년 준호는 자기 전에 내일 할 일을 미리 적어두는 습관이 있다. '아침 운동하기', '책 30분 읽기', '방 정리하기'를 찍찍이에 입력해둔다. 다음 날, 하나씩 완료할 때마다 체크하면서 성취감을 느끼고, 저녁에는 3개의 새로운 스티커를 획득했다."

### 스토리 3: 스티커 수집의 재미
> "초등학교 2학년 서연이는 스티커 모으는 것을 좋아한다. 찍찍이 앱의 스티커 모음판을 자주 확인하며, 아직 받지 못한 레인보우 유니콘 스티커를 얻기 위해 오늘도 열심히 할 일을 완수한다. 친구들에게 자신이 모은 스티커를 자랑하는 것도 재미있다."

### 스토리 4: 실수로 체크했을 때
> "초등학교 4학년 지훈이는 실수로 '피아노 연습하기'를 완료 체크했다. 아직 하지 않았는데 스티커가 나와버렸다. 지훈이는 체크를 다시 해제하고 피아노 연습을 한 후 다시 정직하게 체크 표시를 한다."

### 스토리 5: 주말 목표 달성
> "초등학교 6학년 유진이는 주말에 '자전거 타기', '영화 보기', '친구에게 편지 쓰기'라는 재미있는 할 일들을 입력한다. 하나씩 완성할 때마다 뿌듯함을 느끼고, 모은 스티커를 보며 보람찬 주말을 보냈다는 생각을 한다."

## Technical Requirements

### Technology Stack
- **프론트엔드**:
  - React Native (모바일 앱 - iOS/Android 동시 지원) 또는
  - React + PWA (웹 앱으로 시작 후 모바일 확장)
  - TypeScript (타입 안정성)
  - Tailwind CSS 또는 styled-components (스타일링)
- **백엔드**:
  - Node.js + Express (API 서버) 또는
  - Firebase (빠른 개발 및 인증, 데이터베이스)
  - RESTful API 또는 GraphQL
- **데이터베이스**:
  - Firebase Firestore (NoSQL, 실시간 동기화) 또는
  - PostgreSQL (관계형 데이터베이스)
  - 로컬 스토리지 (오프라인 지원)
- **인증**:
  - 초기 버전: 로컬 사용자 프로필 (간단한 이름 입력)
  - 향후: Firebase Authentication (소셜 로그인)
- **애니메이션**:
  - Framer Motion (React)
  - React Native Animated API
- **아이콘/이미지**:
  - 자체 제작 스티커 이미지 (SVG 또는 PNG)
  - 무료 이미지 라이브러리 활용

### Architecture
- **클라이언트-서버 아키텍처** (향후 확장성 고려)
- **초기 버전**: 클라이언트 사이드 중심 (로컬 스토리지 사용)
- **향후**: 클라우드 기반 동기화 (여러 기기에서 접근)
- **오프라인 우선 설계** (인터넷 없이도 기본 기능 사용 가능)

### Database Schema (예시)
```
Users
- userId (PK)
- userName
- createdAt

Tasks
- taskId (PK)
- userId (FK)
- taskText
- isCompleted
- createdDate
- completedDate

Stickers
- stickerId (PK)
- stickerName
- stickerImageUrl
- rarity (common, rare, epic, legendary)

UserStickers
- userStickerId (PK)
- userId (FK)
- stickerId (FK)
- acquiredDate
```

### APIs
- `POST /tasks` - 할 일 추가
- `GET /tasks/:date` - 특정 날짜의 할 일 조회
- `PATCH /tasks/:id` - 할 일 완료/미완료 토글
- `DELETE /tasks/:id` - 할 일 삭제
- `GET /stickers` - 전체 스티커 목록 조회
- `GET /user-stickers/:userId` - 사용자가 획득한 스티커 조회
- `POST /user-stickers` - 스티커 획득 기록

### Security
- **데이터 보호**: 초등학생 개인정보 최소화 (COPPA 준수 고려)
- **부모 동의**: 13세 미만 사용자는 부모 동의 필요 (향후)
- **입력 검증**: XSS 공격 방지를 위한 입력 sanitization
- **HTTPS**: 모든 통신 암호화

### Performance
- **로딩 시간**: 초기 로딩 2초 이내
- **반응 속도**: 버튼 클릭 후 0.3초 이내 반응
- **이미지 최적화**: 스티커 이미지 lazy loading
- **오프라인 지원**: 네트워크 없이도 기본 기능 동작

### Non-Functional Requirements
- **접근성 (Accessibility)**:
  - 큰 글씨 및 아이콘 (가독성)
  - 색맹 사용자를 위한 색상 대비
  - 화면 읽기 프로그램 지원 (향후)
- **사용성 (Usability)**:
  - 3번 이내의 클릭으로 모든 기능 접근 가능
  - 초등학생이 도움 없이 사용 가능한 직관적 UI
  - 튜토리얼 또는 가이드 제공 (첫 실행 시)
- **확장성 (Scalability)**:
  - 사용자 수 증가에 따른 서버 확장 가능
  - 스티커 종류 추가 용이
- **유지보수성 (Maintainability)**:
  - 명확한 코드 주석
  - 컴포넌트 기반 개발 (재사용성)
  - 테스트 코드 작성 (Jest, React Testing Library)
- **신뢰성 (Reliability)**:
  - 99% 이상 업타임 목표
  - 에러 발생 시 사용자 친화적 메시지 표시
  - 데이터 백업 및 복구 시스템

## Success Metrics

### 정량적 지표
- **사용자 확보**:
  - 출시 후 1개월: DAU 50명
  - 출시 후 3개월: DAU 100명
  - 출시 후 6개월: DAU 500명
- **참여도 (Engagement)**:
  - 평균 주간 할 일 완료율: 70% 이상
  - 주간 활성 사용자 (WAU): 70% (DAU의 70%가 주 3회 이상 사용)
  - 평균 세션 시간: 2-5분 (할 일 관리 특성상 짧은 세션)
- **재방문율 (Retention)**:
  - Day 1 Retention: 60%
  - Day 7 Retention: 40%
  - Day 30 Retention: 25%
- **스티커 수집**:
  - 사용자당 평균 스티커 수: 주당 10개 이상
  - 전체 스티커 중 50% 이상 수집한 사용자: 30%

### 정성적 지표
- **사용자 만족도**: 앱 스토어 평점 4.5/5.0 이상
- **학부모 피드백**: 자녀의 자기 관리 능력 향상 체감
- **추천 의향**: NPS (Net Promoter Score) 50 이상
- **소셜 미디어**: 긍정적 리뷰 및 SNS 공유

## Timeline and Milestones

### Phase 1: MVP 개발 (4-6주)
- **Week 1-2**:
  - 기획 확정 및 디자인 시안 완성
  - 기술 스택 결정 및 개발 환경 설정
  - 데이터베이스 스키마 설계
- **Week 3-4**:
  - 할 일 추가 기능 개발
  - 할 일 완료 체크 기능 개발
  - 기본 UI/UX 구현
- **Week 5-6**:
  - 스티커 받기 기능 개발 (보상 시스템)
  - 스티커 모음판 개발
  - 내부 테스트 및 버그 수정

### Phase 2: 베타 테스트 (2-3주)
- 타겟 사용자 (초등학생 20-30명) 베타 테스트
- 사용성 피드백 수집 및 개선
- 성능 최적화 및 버그 수정

### Phase 3: 정식 출시 (1주)
- 앱 스토어 또는 웹 배포
- 마케팅 및 홍보 시작
- 사용자 모니터링 및 지원

- 사용자 피드백 기반 개선
- 추가 기능 개발 (우선순위, 부모 모드 등)
- 새로운 스티커 디자인 추가 (월 1회)

## Constraints and Assumptions

### Constraints (제약사항)
- **예산**: 초기 개발은 최소 비용으로 진행 (무료 도구 및 오픈소스 활용)
- **인력**: 소규모 팀 (개발자 1-2명, 디자이너 1명)
- **시간**: 첫 MVP는 6주 내 완성 목표
- **기술**: 크로스 플랫폼 개발로 iOS/Android 동시 지원
- **법적**: 아동 온라인 개인정보보호법 (COPPA) 준수 필요 (미국 시장 진출 시)

### Assumptions (가정)
- 타겟 사용자는 스마트폰 또는 태블릿을 보유하고 있음
- 초등학생은 기본적인 읽기/쓰기 능력이 있음
- 부모는 자녀의 자기 관리 능력 향상에 관심이 있음
- 게임화 요소(스티커, 칭찬)가 동기부여에 효과적임
- 인터넷 연결이 항상 가능하지 않을 수 있음 (오프라인 지원 필요)

## Risks and Mitigation

| Risk | Impact | Probability | Mitigation Strategy |
|------|--------|-------------|---------------------|
| 사용자가 스티커에 흥미를 잃을 수 있음 | High | Medium | 정기적으로 새로운 스티커 추가, 시즌 이벤트, 특별 보상 도입 |
| 초등학생이 앱 사용법을 어려워할 수 있음 | High | Medium | 직관적 UI 설계, 첫 실행 시 튜토리얼 제공, 사용성 테스트 반복 |
| 부모가 앱 효과를 의심할 수 있음 | Medium | Low | 통계 기능 제공, 성공 사례 홍보, 교육적 가치 강조 |
| 경쟁 앱 출현 | Medium | High | 차별화된 디자인과 UX, 지속적 업데이트, 커뮤니티 형성 |
| 기술적 버그 및 성능 문제 | High | Medium | 충분한 테스트, 에러 모니터링 시스템 구축, 빠른 패치 대응 |
| 개인정보 보호 문제 | High | Low | 최소한의 개인정보 수집, 부모 동의 시스템, 법률 자문 |
| 예산 초과 | Medium | Medium | 오픈소스 활용, 무료 티어 서비스 사용, 단계적 기능 출시 |
